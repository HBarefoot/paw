## Executive Summary

Paw is a well-architected Bun/Hono personal AI assistant. The earlier
audits' Critical and High items are essentially fixed. But those reports
were **not a complete picture** — this pass found **2 Critical, 13 High,
25 Medium, and 15+ Low** new issues, plus a lint failure and a stale
`bun.lock`.

The single most serious current problem is that **every web admin shares
one conversation/memory namespace** (`user.id === "web-user"` everywhere),
so any admin can read every other admin's data — including any API keys
the AI has auto-stored.

## 3. New findings by severity

### 3.1 Critical (2)

**C-NEW-1. Every web admin shares one conversation namespace.**
- `src/web/app.ts:1868, 2019` — `searchMessages` filters use `userId: "web-user"`
- `src/web/app.ts:2409, 2526` — `/api/chat`, `/api/chat/stream` hardcode `user: { id: "web-user", name: "Web User" }`
- `src/web/app.ts:2892, 2901, 2908, 2927` — session fork/rename/export/messages endpoints accept any `:id` with no owner check
- `src/web/app.ts:2160` — `/api/memory/:id` delete has no id-format validation and no scope filter
- `c.get("admin")` is set by `src/web/middleware/auth.ts:89-103` but never used for authorization
- **Impact:** Admin B reads Admin A's full chat history, memories, and any API keys the AI auto-stored. Cross-admin deletion primitive.

**C-NEW-2. `pawModal._show()` builds innerHTML from unescaped `title`/`body`/`actions`.**
- `src/web/views/layout.tsx:1410-1412` — string concatenation into `modal.innerHTML`
- Callers: `chat.tsx:1915, 1781, 1878, 1738`; `webhooks-page.tsx:114`; `prompts-page.tsx:45` — pass model-derived text and `err.error` JSON
- **Impact:** Stored XSS. Any memory text, webhook name, or error message containing `</div><img onerror=...>` becomes live HTML. Admin-takeover primitive.

### 3.2 High (13)

1. **H-NEW-1.** Cron "event" action with arbitrary event name. `src/cron/scheduler.ts:396-405` + `src/web/app.ts:2279-2340`. Any admin can fire `kernel:shutdown` or `message:inbound` (bypasses access control via `INTERNAL_CHANNELS` at `kernel.ts:861`).
2. **H-NEW-2.** Cron "tool" action with no skill/permission re-check. `src/cron/scheduler.ts:386-395`. `toolRegistry.execute(action.tool, action.input)` runs with no `plugin`/`sessionId` context. Cron can run `exec_command` regardless of session.
3. **H-NEW-3.** MCP server registration writes to config before testing connection. `src/web/app.ts:2553-2632`. Failed `connectServer` swallowed but entry persisted. Plus the SSRF check in `client-manager.ts:139-148` **misses** CGNAT/ULA/embedded-credentials that `src/security/url-guard.ts:51-82` catches.

8. **H-NEW-8.** Memory text injected into system prompt without sanitization. `src/ai/system-prompt.ts:71-74` + `src/kernel/kernel.ts:979-984`. `feedback/store.ts:19-25` sanitizes; memory text does not. Direct prompt-injection path.

## 4. Security escalation paths

Five concrete attack chains showing how Critical+High items combine.

### Escalation 1: Admin → Other admin's data (C-NEW-1)
1. Admin A signs in, chats "remember my API key: sk-prod-xxxx"
2. Memory store saves it; auto-extract may also persist
3. Admin B signs in
4. Admin B opens `/api/memory/search?q=sk-prod` and reads the key
5. Or: Admin B opens `/api/sessions` and sees A's session, then `/api/sessions/:id/messages` reads full history
6. `session?.user_id` in audit (`app.ts:891`) records A's id, but B sees the data anyway

### Escalation 2: Webhook CSRF (M-NEW-1, M-NEW-18)
1. Admin clicks a malicious link in browser
2. Page makes `POST /api/webhooks` with admin's session cookie and arbitrary payload
3. CSRF middleware checks `Origin`; if `allowedOrigins` includes `localhost` (because `host: 0.0.0.0`), origin check passes
4. Webhook created; attacker controls a slug

### Escalation 3: Hostile cron job (H-NEW-1, H-NEW-2)
1. Admin creates cron: `actionType: "event", payload: "kernel:shutdown"`
2. Scheduler fires `bus.emit("kernel:shutdown", undefined)` → process exits
3. Or: `actionType: "tool", action.tool: "exec_command", action.input: { command: "curl ..." }` → OS command runs as kernel UID

### Escalation 4: Canvas XSS (C-NEW-2, M-NEW-3)
1. Admin stores a memory containing `</div><img src=x onerror="fetch('/api/credentials/anthropic')">`
2. Next time modal renders that memory, payload executes
3. JS calls `/api/credentials/anthropic` with admin's session cookie → API key exfiltrated

### Escalation 5: MCP → data exfil (H-NEW-3, H-NEW-11)
1. Admin registers MCP server pointing at `http://attacker.com/mcp`
2. Server returns `tools/list` with harmless-looking tools
3. AI's tool registry includes them; any user can call them
4. The MCP tool's `call_tool` posts the AI's context (memory, recent messages) to `attacker.com`
